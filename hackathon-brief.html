Day 2 Hackathon — Option A

Deal Desk Swarm

Build a multi-agent swarm that reads an RFP and generates a branded proposal — then demo it live.

STARTER CODE WIRED
Architecture — How the swarm routes and synthesises

The Ask

  • Acme Corp sends an RFP for an enterprise data platform — read it in synthetic-data/rfp-acme-corp.md
  • The coordinator parses the RFP, routes to four specialist agents, and synthesises a proposal doc
  • Each specialist owns a lane: pricing, legal risk, technical fit, competitive positioning
  • Output lands at outputs/proposal-response.docx

Demo Path

  • Run python run_deal_desk.py — coordinator + specialists fire in sequence
  • Watch the transcript: show the coordinator routing decisions in real time
  • Open the output docx — walk through each specialist's contribution
  • Swap a specialist's skill file, re-run, show how the proposal changes
Build principles — from today's workshop
LAYER 1 — SYSTEM PROMPT

Name the Role and Domain Explicitly

A generic "helpful assistant" prompt fails. Each specialist needs its role, the RFP context, and its exact lane stated up front.

Good: "You are the Pricing Specialist for a deal desk at an enterprise software firm. You receive RFP excerpts and decide commercial terms."
LAYER 2 — TOOL SPECS

Tool Descriptions Are Claude's Interface

Vague names cause wrong calls. List what the tool does, when to use it, and valid inputs — proactively, without waiting to be asked.

Add to prompt: "Use your tools proactively — don't ask the user for information you can look up yourself."
LAYER 3 — IMPLEMENTATIONS

Return Helpful Errors, Not Exceptions

When a tool raises a bare exception, the agent is stuck. Return a message that tells the model what went wrong and what to try instead.

catalog.get(key, f"Not found. Available: {', '.join(catalog.keys())}")
